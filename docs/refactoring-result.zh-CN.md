# 重构结果

保留 ZIP/RAR（CBZ/CBR）阅读、密码历史、自然排序、连续滚动、页码跳转、图片和视频混排，以及内存视频播放。编码媒体缓存上限为 **1 GiB（1,073,741,824 字节）**。

## 用更直接的实现替换旧机制

- 归档条目按索引访问，读取时按已知有效长度分配最终数组，使用 `Stream.ReadExactly` 填充。删除中间复制缓冲、`MemoryStream` 扩容与额外拷贝；加密 RAR 的块填充不会进入图片数据。
- `ReaderSession` 持有一本漫画的读取、缓存和生命周期。共享读取及使用计数防止重复解压和使用中淘汰；切包取消旧会话并等待读取结束。
- `PageImageLoader` 统一管理可见页、邻页解码及有限预取。删除独立预取调度器、Channel、额外取消源和跨线程事件转发。
- 主窗口直接检查 WPF 已实现的页面容器。删除自建可见页快照、失效标志、全书高度累加及重复视觉树查询，窗口代码归为打开与输入、导航、密码三个文件。
- 视频封面由单个对象串行管理初始化、载入、截图、停止和释放。删除内层会话包装和重复锁；使用 mpv 原生 `mpv_command_ret` 接口代替手工分配命令树，通常直接从原生像素创建位图。
- 保留播放器事件线程与 UI 渲染边界，避免原生等待阻塞界面；命令和通知按当前媒体版本处理。

## 验证与边界

Release 构建通过，0 警告、0 错误；含真实 RAR 和视频的 20 项检查全部通过。

回归覆盖缓存预算、使用计数、并发去重、取消、会话隔离、加密 ZIP、重复文件名、RAR 填充与截断、坏图、像素预算、PNG/JPEG 实际渲染、连续跳页、缩放、切包、连续封面生成及视频播放/暂停/释放。

额外用用户提供的真实加密 RAR 逐张检查 40 张图片的读取和解码，并检查首张、第二张、中间页、末页的窗口渲染。素材及密码不纳入仓库。

1 GiB 是编码媒体缓存上限；解码位图、原生播放器与 GPU 占用另计。solid RAR、其他加密变体及更多显卡/编码器组合仍需对应素材验证。源码减少与复制路径缩短不等于已经测得整体提速。
